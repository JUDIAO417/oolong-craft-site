乌龙茶的地盘 · 赞助名单怎么改（微信赞赏码版）
==============================================

这一版没有任何后端：不用 PHP、不用数据库，整站静态托管就能跑
（GitHub Pages / Netlify / 宝塔任意静态目录都行）。

一、放你的微信赞赏码
  把 qr.png 换成你自己的微信赞赏码截图，文件名保持 qr.png 不变。
  建议正方形、边长 480 以上，太小扫码会糊。
  页面优先读同目录的 qr.png；万一找不到（比如单文件 html 单独发给别人），
  会自动切到内嵌在 html 里的那份码，所以不会出现裂图。

二、改目标金额
  两个地方任选其一：
  1) index.html 里 <section id="sponsor" data-target="500">，改数字即可；
  2) sponsors.json 顶层的 "target": 500。
  （两边都写了的话，以 sponsors.json 为准）

三、改名单（sponsors.json）
  {
    "target": 500,
    "list": [
      {"name":"茶里",  "msg":"壶一直热着，别熄火", "amount":50, "time":"2026-11-22 21:10"},
      {"name":"夜雨茶","msg":"夜里也能摸黑挖点矿", "amount":15, "time":"2026-11-21 23:44"}
    ]
  }
  · 数组顺序就是显示顺序，最新的加到最上面；不排名次，只列名字和金额
  · amount 会自动相加算成「已筹总额」，能量条百分比也自动算，不用手算
  · 金额显示为 ¥ 多少，想在名单里写金额就直接填 amount
  · name 超过 16 字会被截断，msg 超过 60 字会被截断（前端有长度限制，防止排版炸掉）
  · 想清空就写 "list": []

四、用户付款后怎么上榜
  微信个人赞赏码没有任何支付回调，也带不了付款备注，所以做不到"自动上榜"。
  现在的流程很短：
    点「赞助一壶茶」→ 弹窗里直接就是你的赞赏码（没有选金额、填昵称这些步骤）
    → 扫码付款 → 想留个念可以点「我已赞赏」看致谢卡和彩带。
  你收到微信的收款通知后，手动往 sponsors.json 的 list 顶部加一条，刷新页面即生效。
  想让对方留名字，最实际的办法是让他付完在群里说一声（昵称+金额），你手动记。

五、自检
  改完 sponsors.json 直接刷新页面：能量条总额、百分比、名单应该一起变，
  前提是放到 http 服务器（或 GitHub Pages / 宝塔）上访问。
  双击打开本地 html 时名单会显示"读不到"——因为 file:// 下不让读 json，
  放到服务器（或起个 http 服务）就正常，这是浏览器限制，不是 bug。

六、弹窗和名单的位置
  首屏按钮组第三颗「赞助一壶茶」
  独立区块 id="sponsor"：左边文案 + 续航能量条 + 赞助按钮，右边一张半透明玻璃卡贴着赞助名单（只列名字与金额，不排名次）
  弹窗 id="spModal"：打开就是赞赏码


七、这次修的两个问题
  1) 弹窗里赞赏码裂开：单文件 html 单独打开时找不到同目录 qr.png。
     现在 html 内嵌了一份赞赏码做兜底（data URI），同目录有 qr.png 仍优先用它。
  2) 单文件 html 里其它图也内联了（首屏图、合影、地图、头像都转成内嵌），
     所以「主页-含赞助入口-龙井茶.html」可以直接双击打开，不用带 assets 目录。
     代价是文件变大到约 2.0 MB。


八、名单显示「暂时读不到」是怎么回事
  index.html 里那一版是去读同目录的 sponsors.json：
  1) 单文件 html 单独发出去，旁边没有这个 json；
  2) 或者本地双击打开（file:// 协议），浏览器直接禁止读本地 json。
  两种情况下读取都会失败，于是掉进兜底提示。
  现在的做法：html 里存一份名单快照，读不到 json 就用快照，所以双击也能看到
  龙井茶 ¥50 / 茶里 ¥50 / 夜雨茶 ¥15 / 阿青 ¥10 这四条。
  部署到服务器后优先读 sponsors.json，快照不会顶替真实数据。
